NetProbe

一台服务器能连上什么、连得多快、连不上是卡在哪一层—— NetProbe 把这些说不清的网络问题，变成可量化、可追溯的数字。

Python stdlib only Flask SQLite systemd

它能测什么

"网络不通"是个过于笼统的说法。是 DNS 没解析出来？TCP 握手被拒？还是 TLS 协商就卡住了？ NetProbe 按层拆开测，让你知道问题究竟停在哪一步。

tcp

TCP 连通

能不能建立连接，握手花了多久。最基础的通断判断。

tls

TLS 握手

HTTPS 站点的加密协商耗时。跨境站点卡在这一层很常见。

http

HTTP 响应

状态码加上完整的响应时间，判断对方是拒绝还是单纯慢。

dns

DNS 解析

指定 DNS 服务器是否应答、响应多快。解析慢会让所有访问都慢。

icmp

ICMP 通断

ping 的往返延迟与丢包率，看链路质量的底色。

speed

下载测速

对指定 URL 测真实吞吐量。已有实现，按需启用。

测谁

目标清单写在一个 JSON 文件里，随时增删。默认按三类分组，一眼看出差异在哪。

SELF

自有节点

自己的小主机、VPS、云服务器之间互测，确认隧道和映射是否正常。

ABROAD

境外站点

GitHub、Cloudflare 这类，看跨境链路的真实质量。

DOMESTIC

国内站点

主流云厂商与公共 DNS，作为对照组，衡量跨地域延迟基线。

怎么跑起来的

三层结构，各管一件事。探测器只用 Python 标准库，零第三方依赖， 2 核 / 1.6G 的小机器跑起来毫无压力。

快速开始

# 1. 装看板依赖（探测器零依赖）
pip3 install flask

# 2. 改目标清单
vim config/targets.json

# 3. 先跑一轮看看
python3 prober/run.py

# 4. 交给 systemd 常驻
systemctl enable --now netprobe.timer
systemctl enable --now netprobe-web

# 5. 本地访问看板
curl http://127.0.0.1:8088
为什么这个页面上看不到实时数据？
因为这里是 GitHub Pages，它只托管静态文件，跑不了 Python。 真正的看板在服务器上常驻运行，含内网拓扑信息，只对授权访问开放。 这个页面本身，是一个"静态外壳 + 动态数据源"分工的例子。
